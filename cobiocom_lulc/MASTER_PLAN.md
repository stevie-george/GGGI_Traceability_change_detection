**Goal:** train the land-use classifier (avocado / agave / forest / crops / …) across the
8-state COBIOCOM corridor by having 3 photo-interpreters label a **representative sample**
of tiles. The model then classifies *every* tile automatically — we do **not** hand-label
all 1,182 tiles.

**Horizon:** ~5 months · **Mon Sep 7, 2026 → ~Jan 25, 2027.**

> top of that file (sample density, weeks, split, state order) and re-run
> `run_producer.bat plan_sample.py` to regenerate the numbers below.

## 1. Method — why a sample

Supervised classification learns each class from example polygons; it does not need a
polygon in every tile. We take a **systematic spatial sample**: every 2nd row and column
of each state's 20 km grid (~1 tile in 4), so the sample is evenly spread and captures the
north→south gradient (Los Altos agave → central forest → southern avocado). Small states
fall back to all tiles. This turns 1,182 tiles into **338 to label**.

Density is the `STRIDE` knob in `plan_sample.py` (2 = 1-in-4). Raise it for fewer tiles,
lower it for more.

## 5. The weekly loop (same every week)

Run from `cobiocom_lulc`. Output goes to the SSD automatically (the `out/` junction).

1. **Generate** the week's tiles (one call, all consultants):
   ```bash
   run_producer.bat s2_export.py --states <CVE> --tile-ids <all tiles this week>
   ```
2. **Rebuild** the QGIS project so the new tiles become layers — in the QGIS **Python Console**:
   ```
   exec(open(r'C:\Users\StephaniePatriciaGeo\Documents\deforestation_alert\cobiocom_lulc\make_qgis_project.py').read()); main()
   ```
3. **Package** each consultant's update (ships only the new renders, keeps their labels):
   ```bash
   run_producer.bat package_for_consultants.py --name <bundle> --consultant <N> --update --tiles <that consultant's tiles this week>
   ```
4. **Send** each `cobiocom_labeling_<bundle>.zip`; the consultant unzips it **into their
   existing project folder** (merge/replace) — new tiles appear, their polygons are safe.

`--consultant N` reads the assignments from `tile_grid.gpkg`, so the project always
references that consultant's full cumulative set. **One-time setup** before week 1 stamps
the Jalisco sample into that file:
```bash
run_producer.bat plan_sample.py --apply
```
(keeps the pilot marks, so Mau still owns r003c015 and Rodrigo r003c016).

El **plan completo de los 8 estados** está en **`plan_all_states.csv`** (`plan_sample.py --dump`):
una fila por tile muestreado con `state_cve`, `tile_id` (ya prefijado), `consultant`, `week`
(332 tiles asignados + 6 de cola).

**Para descargar un estado (cuando toque implementar):**
1. Filtra `plan_all_states.csv` por `state_cve` (y `week`/`consultant` para armar batches).
2. `run_producer.bat s2_export.py --states <cve> --tile-ids <esos tile_ids>`
3. Empaqueta por consultor: `package_for_consultants.py --name <bundle> --update --tiles <...>`

## 8. Knobs & judgment calls

- **Density** — `STRIDE` in `plan_sample.py` (2 = 1-in-4 = 338 tiles).
- **Pace / windows** — `WK_TOTAL` (21), `HELPER_WEEKS` (8), `TONA_SHARE` (0.75).
- **State order** — the `ORDER` list.
- **Stop early:** once validation accuracy plateaus (your phase-2 Collect Earth / Olofsson
  exercise), you can stop before finishing the sample — the classifier already generalizes
  to unlabeled tiles. Treat the back-half states as *diminishing-returns* coverage.
